# 数据库设计规范

> 本文档规范 siargo 项目的数据库命名、字段类型、索引设计和表结构。

---

## 一、命名规范

### 1.1 表名

| 规则 | 示例 |
|------|------|
| 业务表前缀 `siargo_` | `siargo_customer`, `siargo_qareport` |
| 系统表前缀 `jb_` | `jb_user`, `jb_role`, `jb_permission` |
| 全部小写 + 下划线 | `siargo_equipment_comparison` |
| 不使用复数 | `siargo_customer`（非 `siargo_customers`） |

### 1.2 字段名

| 规则 | 示例 |
|------|------|
| 全部小写 + 下划线分隔 | `order_id`, `create_time`, `next_inspection_date` |
| 关联外键：`表名_id` | `equipment_id`, `report_id`, `category_id` |
| 操作人字段：`角色_id` | `creator_id`, `auditor_id`, `uploader_id` |
| 时间字段：`动作_time` | `creator_time`, `auditor_time`, `upload_time` |

## 二、字段类型规范

### 2.1 主键

```sql
id BIGINT NOT NULL PRIMARY KEY
-- 使用雪花算法生成，不使用 AUTO_INCREMENT
```

### 2.2 字符串

```sql
name        VARCHAR(255)    -- 名称/标题（可变长）
model       VARCHAR(100)    -- 型号
file_path   VARCHAR(500)    -- 文件路径
description VARCHAR(1000)   -- 长描述
remark      TEXT            -- 备注（超长文本）
md5_hash    CHAR(32)        -- MD5 哈希（固定长度）
```

### 2.3 数值

```sql
-- 整数
qi          INT             -- 数量
sort_rank   INT             -- 排序
status      TINYINT         -- 状态标志位
rep_type    TINYINT UNSIGNED

-- 小数
cuc         DOUBLE(4,2)     -- 保留2位小数
pv          DOUBLE(5,3)     -- 保留3位小数
bv          DOUBLE(5,4)     -- 保留4位小数
```

### 2.4 日期时间

```sql
-- ★ 使用 datetime（非 timestamp）
create_time     DATETIME DEFAULT CURRENT_TIMESTAMP
delete_time     DATETIME
upload_time     DATETIME DEFAULT CURRENT_TIMESTAMP
last_inspection_date  DATE           -- 纯日期
next_inspection_date  DATE
active_date           DATE
```

**为什么不用 timestamp**：timestamp 有 2038 问题，且自动依赖时区，datetime 更可控。

### 2.5 状态/标志字段

```sql
-- 使用 tinyint，注释中标注枚举含义
status      TINYINT DEFAULT 1   -- 1=正常, 0=删除
is_active   TINYINT DEFAULT 1   -- 1=生效, 0=失效
vd          INT                 -- 1=有效, 0=已删除
insp        TINYINT             -- 1=待检, 2=精度, 3=外观, 4=包装, 5=完成
audit_status TINYINT DEFAULT 0  -- 0=待审核, 1=审核通过
```

## 三、软删除模式

siargo 项目使用两种软删除模式：

### 模式 A：status + deleted_time

```sql
-- 适用：DMS文件、设备证书、图片管理
status       TINYINT DEFAULT 1    -- 1=正常, 0=删除
deleted_time DATETIME             -- 删除时间
```

### 模式 B：vd + delete_time + delete_des

```sql
-- 适用：检验报告单产品（有回收站需求）
vd           INT                 -- 1=有效, 0=已删除
delete_time  DATETIME            -- 删除时间
delete_des   VARCHAR(255)        -- 删除原因
```

## 四、索引规范

### 4.1 索引类型

| 场景 | 索引类型 | 示例 |
|------|---------|------|
| 外键关联字段 | INDEX (MUL) | `equipment_id`, `report_id`, `category_id` |
| 唯一约束字段 | UNIQUE KEY | `equipment_no`, `name`(分类) |
| 常用查询条件 | INDEX (MUL) | `status`, `next_inspection_date`, `upload_time` |
| 主键 | PRIMARY KEY | `id` |

### 4.2 索引原则

1. 每个外键字段 = 一个 INDEX
2. WHERE 条件中频繁出现的字段 = INDEX
3. ORDER BY 字段 = INDEX（如 `upload_time DESC`）
4. 唯一性约束 = UNIQUE KEY
5. 复合索引按查询频率和区分度排序

## 五、数据库查询规范

### 5.1 MCP MySQL 连接方式

siargo 项目规定**必须通过本地 MCP MySQL 服务**查询数据库：

| 参数 | 值 |
|------|-----|
| host | `127.0.0.1` |
| user | `root` |
| password | `siargo` |
| database | `siargo` |

### 5.2 可用 MCP 工具

| 工具 | 功能 |
|------|------|
| `connect_db` | 连接数据库 |
| `list_tables` | 列出所有表 |
| `describe_table` | 查看表结构（字段/类型/索引/默认值） |
| `query` | 执行 SELECT 查询 |

### 5.3 禁止事项

- **禁止** 查询 `src/main/resources/sql/` 目录下的 SQL 文件（仅作备份用途）
- **禁止** 直接连接生产数据库
- **始终** 以 MCP MySQL 查询到的实际表结构为准

## 八、新增表操作流程

1. 设计表结构（遵循本规范）
2. 在数据库中执行 CREATE TABLE
3. 配置 `dbconfig/mysql/config.properties` 中的 `model_package`
4. 运行 JBolt 代码生成器 → 自动生成 `base/Base*Model.java`
5. 手动创建业务 Model 类（继承 BaseModel + @TableBind 注解）
6. 创建对应的 Service 和 Controller
7. 创建对应的前端页面（`_view/admin/siargo/模块名/`）
