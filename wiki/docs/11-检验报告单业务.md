## 用途、入口与业务粒度

`/admin/siargo/qarep` 管理检验报告头及其产品，从录入、检验签名、批准放行到回收站。一个报告头可以包含多个产品卡片；列表、审批、驳回、导出选择主要以产品记录为操作单位。不能把一个列表行或一个产品 ID 当作整份报告头。

| 实体 | 内容与关系 |
|---|---|
| `siargo_qareport` | 报告头：`order_id`、`cust_id`、`formnum`、`rep_type`、`create_time` |
| `siargo_product` | 产品：`report_id` 指向报告头；保存型号、编号、数量、参数、检验状态、签名及 PDF 地址 |
| `siargo_product_reject_log` | 一个产品多条驳回记录；保存发生环节、原因、操作人及时间 |
| `siargo_prod_model` | 产品通过 `siargo_prod_model_id` 关联的系列/目录分支，管理规则见 [产品目录](10-产品目录与参数.md) |
| 客户及字典 | 客户来自 [客户管理](09-客户供应商与来料图片.md)；报告类型、版号、流量范围及状态显示使用相应字典 |

报告类型 `rep_type=1` 为正常/产成品，`2` 为返修品。`qsi` 是送检数量，`qi` 是检验数量；它们与产品记录条数是不同概念。全部报告指标和统计时间口径只在 [首页看板与报告统计](15-首页看板与报告统计.md) 定义。

## 页面与主要操作

以下地址均以 `/admin/siargo/qarep` 为前缀；表格中的参数是现有调用契约，不表示 Controller 对所有 action 都限定了 HTTP 方法。

| action | 输入与用途 |
|---|---|
| `index`、`datas` | 主页面及分页；`keywords` 按订单号模糊查询，`prodType` 按关联系列类型，`insp` 按产品状态，`dateRange` 按报告创建日期 |
| `add`、`save` | 新建一个报告头及多个独立产品卡片 |
| `edit/{id}`、`update` | `{id}` 是产品 ID；编辑该产品及其共享报告头 |
| `details?id=...` | 以产品 ID 定位报告头，并展示其下有效产品及流程信息 |
| `editDes/{id}`、`updateDes` | 单独编辑产品描述；提交 `product.id`、`product.des` |
| `approval` | 审批工作台，接收操作编码 `insp` 与逗号分隔产品 `ids` |
| `batchInspection` | 执行选中产品的检验/批准操作，参数同上 |
| `batchReject` | 逗号分隔产品 `ids`、必填 `rejectDes` |
| `rejectHistory?productId=...` | 查看产品完整驳回历史，实际 SQL 按日志 ID 升序排列 |
| `inactiveList`、`inactiveDatas` | 回收站及其分页数据 |
| `deleteByIds`、`restore/{id}`、`permanentDelete` | 移入回收站、恢复、永久删除 |
| `addFlowRange`、`saveFlowRange` | 报告表单内新增固定流量范围字典选项 |

`dateRange` 使用 `yyyy-MM-dd~yyyy-MM-dd`。列表日期筛选取 `siargo_qareport.create_time`，与月份归档、年度统计使用的批准时间不同。`prodType=0`、`insp=0` 表示不按该项限制。列表返回 `id`（报告头 ID）、`spid`（产品 ID），均为字符串；`sp_model/sp_number/sp_qsi/sp_qi/sp_des/sp_pdfstr` 是列表字段，不是新增表单的字段前缀。

Excel 预填、报告版号模板、PDF 生成及批次结果协议统一见 [Excel 导入与 PDF 输出](12-Excel导入与PDF输出.md)。

## 新增报告与产品字段

新增提交普通表单，报告头和公共选项保留表单前缀，逐产品内容放入 `productsJson` 字符串。

| 范围 | 请求字段 |
|---|---|
| 报告头 | `qareport.order_id`、`qareport.cust_id`、`qareport.rep_type` |
| 公共选项 | `product.pdfver`、`product.insp` |
| 产品卡片 | `productsJson`：对象数组的 JSON 字符串，每项含下表字段 |

| 产品卡片字段 | 含义与基础校验 |
|---|---|
| `siargo_prod_model_id` | 正整数字符串，指向有效系列/分支；不接受 JSON 数字代替字符串 |
| `model`、`number` | 完整型号与产品编号，均必填且分别不超过 255 字符 |
| `qsi`、`qi` | 必填非负整数，`qsi >= qi` |
| `des` | 产品描述，不超过 1000 字符 |
| `lt_status` | 必须显式选择：`1` 有成品检漏，`2` 无成品检漏 |
| `flow_range` | 流量范围，不超过 255 字符 |
| `cuc/cucmax/cucmin/pv/fl/bv` | 可空的电气数值，必须是有限数值并通过各项范围校验 |
| `thv/zp/la` | 可空整数，分别为热头电压、零点内码、本地地址，并有各自上限 |

一个报告需要 1—500 个产品卡片，`productsJson` 长度不能超过 2,000,000 字符。公共 `pdfver/insp` 由服务端应用到每张卡片，不取卡片自行提交的同名值。`pdfver` 保存启用字典 `siargo_pdfver` 的 **name**，如 `G/2`，不是字典 SN。新增不接受已有报告 ID、产品 ID 或客户端指定的 `report_id`、签名字段。

新增 `product.insp` 只允许 `1`（精度待检）或 `2`（精度已检录入）。选择 `2` 时服务端以当前用户/时间补精度签名；有检漏产品实际保存为 `6`，无检漏产品保存为 `2`。这属于录入路径，与下文按角色审批的操作入口应区分。

保存前校验订单号为正数、客户存在、报告类型为 1/2、版号存在且启用，以及每张卡片的基础字段、系列和电气参数。当前电气阈值集中在 `QarepConst.validateElectricalParams`，不要只依据界面提示文案重新推算边界。空电气值允许录入；模板中需要的未填项由导出链处理。

报告头、编号分配及全部产品在同一事务保存，任一卡片失败则整体失败。成功结果包含 `data.reportId` 和 `data.productIds`，均使用字符串 ID。编号由服务端 `creatFormnum/saveReportHeader` 生成，客户端不能提供编号替代。

## 检验状态、审批操作与签名

`insp` 表示产品当前所处的待办环节或完成状态。前端历史字段名 `accq/funq/appq/allq` 不能按英文词面重新解释业务步骤。

```mermaid
flowchart LR
  A[1 精度待检] -->|无成品检漏| C[2 外观待检]
  A -->|有成品检漏| B[6 成品检漏待检]
  B --> C
  C --> D[3 包装待检]
  D --> E[4 待批准]
  E --> F[5 已完成]
```

`batchInspection` 的请求 `insp` 是历史沿用的操作编码，不能直接作为本次写入的目标状态。实际映射如下：

| 操作 | 请求 `insp` | 要求当前状态 | 成功后状态 | 本次签名 | 角色 SN |
|---|---:|---:|---|---|---:|
| 精度检验 | 2 | 1 | 有检漏→6；无检漏→2 | `accq_uid/accq_time` | 211 |
| 成品检漏 | 6 | 6 | 2 | `lt_uid/lt_time` | 215 |
| 外观检验 | 3 | 2 | 3 | `funq_uid/funq_time` | 212 |
| 包装检验 | 4 | 3 | 4 | `appq_uid/appq_time` | 213 |
| 批准放行 | 5 | 4 | 5 | `allq_uid/allq_time` | 214 |

Controller 入口要求 `PermissionKey.SIARGO`，有系统管理员豁免。审批 Service 再按操作校验 `RoleService.hasRoleOrAbove`，支持角色树中上级功能角色（`type=1`）覆盖及管理员角色规则，菜单角色（`type=0`）不参与覆盖；页面按钮显隐不是最终授权依据。产品行加锁后，还以当前 `insp` 和 `vd=1` 为条件更新，状态不符的行不会被强行跳过环节。

批量审批允许部分成功：全部失败返回失败；至少一行成功时提交成功行，并用成功响应的 `msg` 列出未成功产品。调用方必须展示这段提示，不能只看到成功状态就认为全选行都已推进。

### 驳回

驳回按产品 **当前状态** 判断操作者角色，与审批操作编码不是同一映射。必须填写原因，`1` 和 `5` 不可通过此入口驳回。

| 当前状态 | 所需角色 SN | 回退状态 | 清空的完成签名 |
|---:|---:|---|---|
| 6 | 215 | 1 | `accq` |
| 2 | 212 | 有检漏→6；无检漏→1 | 分别清 `lt` 或 `accq` |
| 3 | 213 | 2 | `funq` |
| 4 | 214 | 3 | `appq` |

成功更新状态后调用 `ProductRejectLogService.saveLog` 追加历史，日志保存成功后增加累计次数；详情可显示各环节历史及最近一次驳回。当前调用方没有使用 `saveLog` 的布尔返回值决定结果，计数更新异常也只记日志，因此不能把审批响应成功当成历史与冗余计数均已核验。批量驳回同样允许部分成功，并返回失败产品明细。批量结果与状态流转的事务提交边界见 [Service 指南](03-Service层开发指南.md)。

## 编辑与当前权限边界

完整编辑提交 `qareport.id/order_id/cust_id/rep_type` 和 `product.id`、产品可编辑字段、`product.insp`。Service 核对产品确属该报告头、仍有效，并以白名单复制业务字段；请求中的签名人、签名时间和报告归属不直接写入。

**当前后端完整编辑支持 `insp=1—6`，并没有“仅精度待检可编辑”的统一限制。** 编辑页面把原 `insp` 放在隐藏字段；后端仍接受合法范围内的状态变更，前进时补齐缺少的签名，回退时清掉目标状态不需要的签名。已有签名以 `COALESCE` 保留。该路径没有复用 `batchInspection/batchReject` 的逐环节角色校验，不能将审批入口的保护描述为所有编辑入口都具备。

变更成品检漏标记也会归一化状态：外观待检由无检漏改有检漏时回到 `6`；检漏待检改为无检漏时进入 `2`。最终状态 `6` 只允许有检漏产品。已有停用系列可在编辑时保留原关联，改选其他系列必须有效；该项与目录的删除/停用规则统一见 [产品目录](10-产品目录与参数.md)。

单独描述编辑只要求产品有效、描述长度合法，没有单独的检验状态限制。共享报告头修改会影响同报告的全部产品；相关 PDF 失效和清理规则见 [输出生命周期](12-Excel导入与PDF输出.md)。

## 回收站、字典选项与通知

移入回收站必须填写 `delete_des`，产品置 `vd=0` 并记录 `delete_time`；不会重置其原检验状态，也不等于删除 PDF 文件。恢复以产品 ID 操作，置 `vd=1` 并清删除说明和时间。当前恢复 Service 没有额外核验“原状态必须是回收站”的条件，不应把 UI 使用方式写成服务端强制限制。

永久删除只允许现存目标产品全部处于回收站，否则整批拒绝。成功时删除驳回历史与产品；同报告下不再有任何产品（含回收站）才删除报告头。不存在的产品 ID 跳过。PDF 路径在锁内收集、提交后按引用情况清理；文件清理失败会记录日志，不能声称数据库提交与磁盘删除是一个可回滚事务。

报告内新增流量范围只接收 `name` 和 `sn`，服务端固定字典类型为 `siargo_flow_range`、父级为 0；名称及编码各不超过 40 字符。类型不存在或停用时拒绝，不允许请求指定其他字典类型、父级或记录 ID。

当前待办通知只在 **批量包装检验成功、请求 `insp=4`** 后触发，通知直接拥有角色 SN 214 的用户；其他检验环节通知关闭。每用户已有同类未完成待办（状态 1/2）时跳过，新待办规定完成时间为 15 天后。待办事务成功后发送 `EventKit` 事件；通知异常记录日志，不撤销已提交的检验操作。普通编辑把状态改到 4 不会经过此通知调用链。
