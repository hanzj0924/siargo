# 项目配置速查手册

> 核对日期：2026-09-30；源码基线：Siargo v2.9.4 / `18c1de8`。以下为仓库配置快照和代码加载方式，不代表运行服务器的实际值；未启动、重启或打包。返回[文档导航](README.md)。

## 配置来源与生效边界

| 来源 | 作用 |
| --- | --- |
| [application.properties](../../src/main/resources/application.properties) | `pdev` 环境选择、系统标识、指定 CSS/JS 清单 |
| [config.properties](../../src/main/resources/config.properties) / [config-pro.properties](../../src/main/resources/config-pro.properties) | 开发 / 生产主配置、业务文件根目录、缓存和功能开关 |
| `src/main/resources/dbconfig/mysql/config*.properties` | 对应环境数据库连接、加密标志与生成器配置 |
| [undertow.properties](../../src/main/resources/undertow.properties) | 监听、会话、HTTPS、热更新与压缩 |
| `src/main/resources/caffeine/`、日志配置文件 | 缓存区域与日志输出 |
| `ProjectConfig` / `ExtendProjectConfig` | 实际路由、插件、任务和扩展的装配 |

`Starter.run()` 先执行 `JBoltConfig.loadConfig()`。当前 `pdev=dev`；生产环境使用 `pdev=pro`。切换该项不会自动修改所有 Undertow 配置、外部文件位置或运行进程。用户在核实环境后手动重启才能加载需要启动时读取的配置。

数据库配置只记录字段用途，不复制账号、密码、AppSecret、地图密钥或加密串。`is_encrypted` 必须匹配真实保存方式；`db_type`、`jdbc_url`、`db_name`、`db_schema`、`id_gen_mode`、`model_package` 分别涉及数据库类型、连接、命名和模型生成行为。生成目标还受入口代码影响：当前 `ModelGenerator` 向 `JBoltProjectGenConfig.init(...)` 显式传入 `modelPackage`、`tableNames`、`idGenMode` 等参数，不能仅修改配置文件便认定生成目标已切换；具体流程见 [Model 指南](04-Model层开发指南.md)。旧 SQL 备份不作为当前结构或自动初始化来源。

## 当前主要开关

| 配置项 | 开发 / 生产仓库值 | 说明 |
| --- | --- | --- |
| `dev_mode` | `true` / `false` | JFinal 开发模式 |
| `engine_dev_mode` | `true` / `false` | Enjoy 模板开发模式 |
| `dbsql_engine_dev_mode` | `true` / `false` | SQL 模板引擎开发模式 |
| `global_default_id_gen_mode` | 均为 `snowflake` | 默认主键策略 |
| `jbolt_cache_type` / `jbolt_cache_name` | `caffeine` / `jbolt_cache` | 平台缓存实现及配置名 |
| `jbolt_websocket_enable` | 均为 `true` | 是否注册 WebSocket 入口 |
| `jbolt_ureport_enable` / `sentinel_enable` | 均为 `false` | 可选报表 / 限流集成关闭 |
| `jbolt_global_upload_to` | 均为 `local` | 当前统一上传目标 |
| `jbolt_code_gen_enable` | `true` / `false` | 可视化生成器路由开关 |
| `jbolt_code_gen_class_scan_packages` | 均为 `cn.jbolt` | 生成器枚举、缓存和 Service 等发现范围 |
| `jbolt_proxy_type` | 均为 `jfinal_proxy` | 动态代理实现 |
| `max_post_size` | 均为 `102400` | 平台配置单位为 KB，约 100 MiB；单接口仍可另有限制 |
| `resolve_json_request_enable` | 均为 `false` | 不应假设任意 JSON 请求自动映射为表单参数 |
| `process_get_request_target_xss_enable` | 均为 `false` | 不是页面输出自动转义的保证 |
| `disallowed_http_methods` | `TRACE,TRACK,PUT,DELETE,PATCH,HEAD,CONNECT` | Starter 配置的拒绝方法集合；现有动作不能凭名称推断 HTTP 方法 |
| `captcha_cache_enable` | 均为 `false` | 验证码缓存配置 |
| `sensitive_word_check_enable` | 均为 `true` | 还需看具体校验调用方 |
| `onstart_check_and_init_dictionary_enable` | 均为 `false` | 字典启动检查配置 |
| `jbolt_druid_dev_mode_full_sql_log` | 均为 `true` | 仓库配置事实，实际输出还受框架模式和日志设置影响 |

`need_always_https`、`domain`、`word_img_inner_domain`、`editor_imghost` 分别影响 HTTPS 要求、域名及资源地址生成；它们不等于 Undertow TLS 已开启。微信、Redis 序列化、Java AWT 与 Oracle 引号配置仍可见于平台配置，但不能据此断言相应业务已启用。参见[原生机制](jbolt-native-mechanisms.md)。

## Undertow 与启动参数

仓库当前监听 `0.0.0.0:80`，`undertow.devMode=true`，会话超时 `1800` 秒，gzip 开启，SSL 与 HTTP/2 关闭。开发入口通常为 `http://127.0.0.1/admin`；真实部署访问地址由运行配置决定。

开发时以 `cn.jbolt.starter.Starter` 为 main 类、项目根目录为工作目录。JDK 25 的 VM 参数遵循[项目 README](../../README.md)和现有启动脚本，保留需要的 `--add-opens`。`ProjectServer` 的版本应与 POM 同步。修改端口或配置属于显式部署操作，本手册编写没有代为执行。

## 业务文件定位

以下配置均相对于 Web 根。开发根通常为 `src/main/webapp/`，发布根为运行目录中的 `webapp/`。

| 配置 | 当前相对路径 | 内容 |
| --- | --- | --- |
| `siargo_imi_upload_path` | `upload/siargo/imi` | 来料图片 |
| `siargo_dms_upload_path` | `upload/siargo/dms` | 技术通知单 |
| `siargo_eqcert_upload_path` | `upload/siargo/eqcert` | 设备证书 |
| `siargo_prod_model_upload_path` | `upload/siargo/prod_model` | 产品资料与尺寸图 |
| `siargo_qarep_export_path` | `export/siargo/qarep` | 成品报告与归档 |

[SiargoStorage](../../src/main/java/cn/jbolt/common/storage/SiargoStorage.java) 读取五个业务根并校验：值必须存在、为合法相对路径、位于 Web 根内；不同业务根不得相同或相互包含。路径校验还检查规范路径、目录边界及符号链接，不能只以字符串前缀代替。URL、物理路径与 JFinal 上传目录是不同表示。

| 入口 | 作用 |
| --- | --- |
| `forBusiness(Business)` | 使用配置中的业务根定位文件 |
| `forReportResources()` | 报告导入内部资源，固定根 `upload/siargo/qarep` |
| `forReportTemplates()` | PDF 模板，固定根 `upload/siargo/qarep/templates` |
| `path()` / `checked()` | 构造并校验物理路径 |
| `resolveUrl()` / `toUrl()` | Web 相对地址与受控物理路径互转 |
| `uploadDirectory()` | 返回相对框架上传根的目录供 Multipart 使用 |
| `moveNew()` / `copyNew()` | 新目标操作，拒绝静默覆盖已有文件 |

[SiargoUploadFiles](../../src/main/java/cn/jbolt/common/storage/SiargoUploadFiles.java) 为每次上传分配独立临时目录，校验原文件名；清理结果含失败清单，移动补偿失败会保留现存文件并报告。它不持有数据库事务，补偿与提交后清理由真正的业务事务所有者安排。

数据库备份不包含附件、模板和导出文件。迁移配置必须同时核对数据库中的相对地址、物理文件、权限和 Web 根；仅修改配置键不会搬运历史文件。CME 的固定学习资料路径及报告模板细节分别见[学习资料](17-学习资料与版本日志.md)和[报告输出](12-Excel导入与PDF输出.md)。

## 缓存与任务

平台 Caffeine 配置与 Service 自维护的字段缓存分别生效。业务缓存的 TTL、筛选维度和失效入口由所属专题定义；不要按平台默认缓存时间推断看板或 API 日志统计刷新时间。事务规则见[Service 指南](03-Service层开发指南.md)。

已注册调度以 `ProjectConfig.configCron4jPlugin()` 为准：在线用户清理每分钟执行。`ExtendProjectConfig` 中被注释的微信媒体下载任务不在运行调度清单内。异步任务不应依赖当前请求线程中的用户身份。

## 环境资源与发布

12 项本地 CSS/JS 由 `application.properties` 中的清单限定，解析器仅在同目录、同基础名间选择源/min 文件，保留 URL 参数及片段。优选规则与完整清单见[前端指南](05-前端开发指南.md)。

正式发布以 [siargo-package.md](../../siargo-package.md)、[package.xml](../../package.xml) 和成功打包基线为准：

1. 同步 POM 与 `ProjectServer` 版本，并按真实业务变更维护发布说明。
2. 调用既有增量压缩流程，仅处理指定清单；日常文档维护不生成 min 文件。
3. Maven 产物组织为 `config/`、`lib/`、`webapp/` 和运行脚本；项目 JAR 使用 `siargo-<版本>.jar`。
4. 在发布暂存目录核对生产配置，并检查最终每个归档的实际内容。仅调整目录而未重新归档，旧压缩包不会随之更新。
5. DMS 附件内容按当前排除规则由用户另行复制，源文件保留。`.codex/` 辅助内容不进入运行包；Wiki 不是应用运行依赖。

发布与业务归档是两件事。报告的月份 RAR 归档使用 `winrar_exe_path` 指向的外部 WinRAR 程序，不能以 Maven 打包成功推断报告归档可用；允许月份、筛选时间和失败结果见[报告输出专题](12-Excel导入与PDF输出.md)。

## 排查入口

| 现象 | 优先核对 |
| --- | --- |
| 配置已改但行为未变 | 运行目录、`pdev`、启动时加载点、是否由用户重启 |
| 新模块 404 | `ProjectConfig` 显式扫描、`@Path` 与实际 action |
| 文件路径拒绝或上传失败 | 五个业务根、Web 根、框架上传根、跨业务路径、临时文件是否存在 |
| 数据保存但回显为空 | 实际 JSON 字段、序列化容器与页面绑定，不先假定缓存 |
| 页面资源缺失 | 12 项清单、源/min 存在性、发布排除规则、模板是否调用 `ProjectAssets` |
| 下线后请求被拒绝 | 活跃会话与 `SiargoTerminalOfflineInterceptor`，不是资料文件丢失 |
| 失败没有异常堆栈 | Service 软失败、响应数据及 `RenderFailLogHandler` 日志 |

排查时只读取必要配置并脱敏，不将整份含凭据的配置复制到文档、终端输出或日志。
