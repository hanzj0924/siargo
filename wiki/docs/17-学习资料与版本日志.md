## 1. 两类文件展示模块

学习资料用于查看注册计量师知识体系、资料目录、PDF/PNG 和专题思维导图；版本日志用于查看已发布功能变更。二者读取部署资源，不以业务表维护内容，也不是通用在线文档编辑器。

| 模块 | 入口 | 权限 | 内容来源 |
|---|---|---|---|
| CME 注册计量师资料 | `/admin/siargo/cme`、`/admin/siargo/cme/learn` | `PermissionKey.SIARGO` | webRoot 下 `_view/admin/siargo/cme/` |
| 版本日志 | `/admin/changelog` | `PermissionKey.SIARGO_CHANGE_LOG` | webRoot 下 `_view/admin/siargo/changelog/CHANGELOG.md` |

两者均有系统管理员权限豁免，进入后台登录权限链。版本日志的权限和 URL 与一般 `admin/siargo/...` 模块不同，菜单维护时必须保留这一差异。

## 2. 学习页面与资料目录

`cme/index` 渲染注册计量师知识体系首页；`cme/learn` 提供左侧资料树、名称搜索和右侧预览。资料树由 `cme/listFiles` 在请求时扫描，根目录只按以下固定顺序展示：

1. 法规。
2. 实务。
3. 案例。
4. 补充知识。
5. 计算器说明书。

缺失根目录跳过，只收录 `.pdf` 与 `.png`，扩展名比较忽略大小写；没有任何受支持文件后代的目录不显示。同级目录在前、文件在后，分别按中文拼音排序。任意放在 CME 根目录的其他新文件夹不会因为存在就自动成为第六个栏目。

目录树通过 `renderJsonData` 返回，数据项为普通 JSON 对象：

```json
{
  "name": "法规",
  "type": "dir",
  "children": [
    { "name": "示例资料.pdf", "type": "file", "fileType": "pdf", "path": "法规/示例资料.pdf" }
  ]
}
```

示例只说明节点结构，不代表实际文件清单。`path` 相对于 CME 资料根目录并使用 `/`；`fileType` 是 `pdf/png`。节点使用 JSON 对象构造，`fileType` 保留驼峰，不应套用业务 Record 的列键小写规则。

学习页搜索过滤已加载的目录和文件名称，不检索 PDF 正文，也不调用全文检索或 AI 问答服务。新增目录类型、文件类型或全文搜索均属于新能力，不能因页面有搜索框就写成已经支持。

## 3. 文件预览与专题页面

选择文件后请求 `cme/viewFile?path=...`，路径在前端使用 `encodeURIComponent` 编码。PDF 放入浏览器 `<embed>`，PNG 以 `<img>` 展示，顶部显示路径面包屑。

`viewFile` 检查非空路径、PDF/PNG 扩展名、规范化后的路径位于 CME 根目录内部以及目标确为存在的文件。通过后设置对应 Content-Type 和 `Content-Disposition: inline`，流式输出文件。路径校验失败、类型不支持或文件缺失都会返回失败信息，不能把它当作成功的 PDF 响应解析。

现有文件输出没有专门实现 HTTP Range 分段读取，页面预览依赖浏览器自身 PDF 支持；源码存在接口不等于本机或移动端已经预览验收。

同时保留三个单独专题入口：

| 主题 | 查看页面 | PDF 流 | 思维导图页面 |
|---|---|---|---|
| 法规 | `cme/fagui` | `cme/faguiPdfSrc`，固定文件 `1法规.pdf` | `cme/faguiMindmap` |
| 实务 | `cme/shiwu` | `cme/shiwuPdfSrc`，固定文件 `2实务.pdf` | `cme/shiwuMindmap` |
| 案例 | `cme/anli` | `cme/anliPdfSrc`，固定文件 `3案例.pdf` | `cme/anliMindmap` |

这些专题是明确的模板及文件映射，不会自动替换成新资料树中的同名文件。维护时要区分“资料树收录文件”和“旧专题固定引用文件”。

## 4. 学习资料维护边界

资料维护以部署资源中的实际文件为准。更新资料时把 PDF/PNG 放入受支持根目录下的合适子目录，保留有意义的文件名；移除文件后目录树下次扫描不再收录，已打开的预览链接仍可能因文件不存在而失败。

当前没有基于数据库的课程、学习进度、测验、资料审批、上传管理或文件版本恢复功能，也没有独立的 Learning 后端模块。删除或替换资料不是 DMS 的文件状态切换，不能套用技术通知单的生效和失效规则。正式资料归属业务资源，不应误迁入 AI 临时目录。

是否需要更新部署资源或重启，由具体部署方式和维护任务决定；文档重写不会自动更新运行中的资料，也不会启动或重启服务。

## 5. 版本日志的读取与格式

`ChangelogController.index` 每次从部署 webRoot 中的 `CHANGELOG.md` 读取 UTF-8 文本，转换为 HTML，再交给 `index.html` 展示。读取的是业务资源内的日志文件，不是项目根目录、Git commit 列表或 wiki。

当前解析器只处理与展示有关的固定格式：

```markdown
### v2.9.4 (2026-09-30)

- 示例业务变化。
- 修正 `某项字段` 的展示。
```

每个行首 `### ` 开始一个版本条目，之后行首 `- ` 归入该版本。版本标题中的 `v主版本.次版本.修订版本` 用于按主次版本分组，组和条目保留文件出现顺序；首组默认展开，页面支持全部展开或折叠。

它不是完整 Markdown 渲染器：任意段落、表格、代码块或多层列表不能保证进入最终展示。标题和条目先做 HTML 转义，条目中的反引号再转换为内联 `<code>`。不要通过在日志中插入 HTML 实现页面结构。

正式日志维护应遵守项目发布流程：功能条目面向使用者写清变化，保持当前解析器能识别的标题和列表；日常未发布变更不提前写入正式版本日志，静态资源压缩本身不作为业务更新条目。版本来源、发布打包和资源环境切换见[项目配置速查手册](08-项目配置速查手册.md)。

日志文件不存在时页面提示“更新日志文件不存在”；读取异常时展示读取失败。文件存在但只有不受支持的格式，可能得不到预期版本内容，排查顺序应为运行时文件位置、UTF-8 内容、`### ` 与 `- ` 格式，再看页面渲染。
