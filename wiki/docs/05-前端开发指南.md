## 1. 当前技术栈与维护位置

业务后台采用 Enjoy 服务端模板、JBolt 页面和组件、jQuery、Bootstrap。当前后台主布局通过 [__jboltassets.html](../../src/main/webapp/_view/_admin/common/__jboltassets.html) 使用 **Bootstrap 4.6.2**；资源目录中同时存在其他版本或第三方组件自带版本，不能据此把后台主栈写成 3.x 或擅自升级为 5.x。

| 内容 | 正式位置 | 维护方式 |
|---|---|---|
| 业务页面 | `src/main/webapp/_view/admin/siargo/<模块>/` | 页面结构、数据传递、必要初始化调用 |
| 业务 JavaScript | `src/main/webapp/assets/js/siargo.js` | 按模块组织命名空间、事件与交互 |
| 业务 CSS | `src/main/webapp/assets/css/siargo.css` | 按模块分区并限定作用域 |
| 平台布局与表单提交 | `src/main/webapp/_view/_admin/common/` | 优先复用，避免为局部需求修改全局行为 |
| 第三方插件 | `src/main/webapp/assets/plugins/` | 复用现有版本和加载机制 |

新增业务逻辑、样式不散落到模板 `<script>/<style>` 或新独立片段中；旧模板中存在内嵌代码不构成新增的依据，也不意味着每次局部修改都要迁移全项目旧代码。不得引入 Vue、React 等冲突前端架构。

## 2. 两种模板与输出安全

| 机制 | 执行位置 | 语法示例 |
|---|---|---|
| Enjoy | 服务端渲染页面时 | `#(...)`、`#if`、`#for`、`#include`、`#define` |
| JBoltTable 客户端行模板 | 浏览器取得列表 JSON 后 | `{@each datas as data,index}`、`${data.name}` |

`#(...)` **不是自动 HTML 转义输出**。JFinal 5.2.7 的 `Output` 直接写出字符串；来自用户输入的文本、代码值和提示内容需按输出位置进行转义。

```html
<span>#escape(customer.name??)</span>
<input name="customer.name" value="#escape(customer.name??)">
```

`??` 处理空值，不防止 HTML 注入。`${...}` 属于客户端模板，不能作为 Enjoy 的另一种输出写法介绍；其转义行为应按实际模板引擎及调用方式核对。拼装 HTML、HTML 属性、URL 或 JavaScript 字符串时，必须按该上下文处理，不能因为某个值曾在文本节点转义过就复用到所有位置。

前端写文本优先使用 `.text()` / `textContent`。不要把动态备注未经处理拼进 `data-content`、事件属性或 `<script>`。富文本确需保留 HTML 时使用业务约定的内容处理链，不能在任意列表列中改用原样输出。

## 3. 页面布局与组件初始化

典型页面使用 `#@jboltLayout()`，主内容定义在 `#define main()` 中。页面内表单、表格、行模板、工具栏等 ID 使用随机 `pageId`，避免同一模块多标签或多弹窗时冲突。

```html
#@jboltLayout()
#define main()
#set(pageId=RandomUtil.random(6))
<div class="jbolt_page" data-key="#(pmkey)">
    <div class="jbolt_page_title">页面标题与工具栏</div>
    <div class="jbolt_page_content">页面内容</div>
</div>
#end
```

页面通过 pjax、ajaxportal 或 Dialog 局部加载时，不应只依赖浏览器首次 `document.ready`。复用平台初始化机制，业务初始化入口放在 `siargo.js`，由页面 `data-init-handler` 或必要的初始化调用连接。

当前客户新增页使用 `data-init-handler="SiargoDialogForm.focusFirstInput"`，对应业务脚本中的公共表单方法。自定义事件应限定当前页面/弹窗作用域，重复打开不能重复绑定或操作另一个窗口的控件。

Enjoy 动态数据通过属性或初始化参数传入；静态 `.js/.css` 内不能包含 Enjoy 指令。

## 4. JBoltTable 列表契约

完整起点见[客户列表模板](../../src/main/webapp/_view/admin/siargo/customer/index.html)。一个 AJAX 列表至少需要相互匹配的行模板、查询表单和表格属性：

| 属性/结构 | 作用 |
|---|---|
| `textarea.jb_tpl_box` | 存放客户端行模板 |
| `data-jbolttable`、`data-ajax="true"` | 由平台初始化表格与数据请求 |
| `data-url` | 后端列表入口 |
| `data-rowtpl` | 行模板 ID |
| `data-conditions-form` | 查询表单 ID |
| `data-page` | 分页组件 ID |
| `data-toolbar` | 关联工具栏 ID |
| `th` 的 `data-column` | 对应实际返回列，参与平台列配置 |

行模板通常由 `{@each datas as data,index}` 遍历 `datas`，雪花 ID 保持字符串。列表查询应与 `renderJsonData(...)` 的实际分页封装配合，不能凭经验创建另一种 `rows/total` 协议。

消费 Record 时使用序列化后的实际小写键。例如 PDF 模板关联的响应是 `modelids/modelnames`，提交参数可以是 `modelIds`。SQL 写了驼峰别名不代表浏览器能读取驼峰属性；完整规则见 [Model 指南](04-Model层开发指南.md)。

表格排序、固定列、刷新、勾选和分页优先调用当前平台已有能力。修改 action 或字段时同时检索表格列、行模板、编辑回显和提交逻辑，避免只修复列表文字。

## 5. 操作按钮与 Dialog

常规按钮使用平台声明式属性：

- 弹窗：`data-dialogbtn`，配合 `data-url`、`data-title`、`data-area` 和现有回调。
- AJAX 操作：`data-ajaxbtn`、`data-confirm`、`data-loading` 与 `data-handler`。
- 表格刷新：沿用对应页面的 `refreshJBoltTable` 等平台 handler，不新建局部失配的刷新链。
- 编辑、删除：优先使用原有 `jbolt_table_editbtn`、`jbolt_table_delbtn` 及图标体系。
- 上移/下移：`jbolt_table_btn` 配合 `fa fa-arrow-up c-info` / `fa fa-arrow-down c-info`，保留原生尺寸、间距和悬停样式；禁止按标题选择器统一加底色、描边或固定尺寸。

复杂弹窗在 `siargo.js` 中通过现有 `DialogUtil` 创建，与平台生命周期、关闭和刷新处理连接。动态内容弹窗应参考当前已实现方法，不直接把脱离 DOM 的 jQuery 对象交给 Layer 并假定版本行为相同。

当前实现可参照 [siargo.js](../../src/main/webapp/assets/js/siargo.js) 中产品参数、PDF 模板和月份区间弹窗。模块输入、流程含义、提交接口分别见[产品目录](10-产品目录与参数.md)、[检验报告单](11-检验报告单业务.md)、[导入与 PDF](12-Excel导入与PDF输出.md)专题。

## 6. 表单、校验与 AJAX

表单字段前缀必须与 Controller 的 `getModel` 一致：`getModel(Customer.class, "customer")` 对应 `customer.id`、`customer.name`。新增与编辑可共用 `_form.html`，提交沿用平台 `_formjs.html`。

```html
<form id="customerForm" action="#(action)" method="post"
      onsubmit="return false;">
    <input type="hidden" name="customer.id" value="#(customer.id??)">
    <input name="customer.name" value="#escape(customer.name??)"
           data-rule="required" class="form-control">
</form>
#define js()
#include("/_view/_admin/common/_formjs.html", formId="customerForm")
#end
```

示例用于说明绑定和提交关系；实际页面需保留自身唯一 ID、字段限制及布局。前端 `data-rule` 提升操作反馈，后端仍需完成同样必要的业务校验。

手动请求优先复用项目已使用的平台 Ajax 对象族，以保留失败提示、锁屏、登录失效和终端下线处理。后台 JSON 常按 `state == "ok"` 判断成功，不机械使用 `result.success`。直接使用 `$.ajax` 的既有场景，改动时必须保留其完整错误处理和页面关闭行为。

关联选择控件初始化时要恢复 ID 和显示名称。数据尚未加载或字段名读错时不能视作用户主动清空；“打开编辑后不改动再提交仍保留原绑定”是此类修改的必要核对场景。

## 7. 样式作用域与流程颜色

业务 CSS 集中到 [siargo.css](../../src/main/webapp/assets/css/siargo.css)，使用页面/模块根类限定作用域，避免裸 `table`、`.btn`、`input` 等选择器影响其他模块或平台弹窗。

流程颜色使用已有 `--flow-*` 变量，页面传递语义键 `acc|leak|vis|pack|appr|done`，不能将业务状态值直接作为连续步骤序号。颜色与阶段定义由[检验报告单专题](11-检验报告单业务.md)维护；局部样式可在模块容器内派生变量，不向模板散写色值。

局部布局请求只调整布局所需的模板/CSS/交互，不顺带修改 API、查询条件、筛选重置或权限。桌面与窄窗口需避免遮挡按钮、裁切弹窗和强制横向溢出，优先沿用现有 Bootstrap 4.6.2 栅格与项目组件。

## 8. 环境加载与指定 12 项资源

[application.properties](../../src/main/resources/application.properties) 的 `pdev` 决定环境，`project_assets.environment_files` 当前仅包含以下 12 项：

| 目录 | 文件 |
|---|---|
| `assets/css/` | `jbolt-admin.css`、`jbolt-mine.css`、`jbolt-page-loading.css`、`jbolt-wechat-menu.css`、`login.css`、`siargo.css` |
| `assets/js/` | `jbolt-admin.js`、`jbolt-mine.js`、`jbolt-wechat-menu.js`、`login.js`、`relogin.js`、`siargo.js` |

同基础名称的 `.min` 文件与源文件视为同一资源。清单内引用通过 `ProjectAssets.url(...)`：

```html
<link rel="stylesheet"
      href="#(ProjectAssets.url('assets/css/siargo.css'))?v=#(JBoltConfig.ASSETS_VERSION)">
```

[ProjectAssetResolver](../../src/main/java/cn/jbolt/common/util/ProjectAssetResolver.java) 的规则为：

1. `pdev=dev` 优先源文件，缺少时使用同目录对应 `.min`；`pdev=pro` 优先 `.min`，缺少时使用源文件。
2. 验证实际文件存在，保留查询参数、版本号和 URL 片段。
3. 外部 URL、CDN、第三方插件及清单外资源不改写。
4. 两种文件都缺少时记录缺失信息；不能凭空生成地址或把压缩内容改名冒充源文件。

日常改动只维护源文件，不更新 `.min`。正式打包前由 `scripts/Compress-ProjectAssets.ps1` 按成功打包基线哈希决定重压范围；变化、基线缺失或产物缺失才处理，全部打包成功后才更新基线。生产发布仍保留需要回退使用的源文件，压缩行为本身不写入业务 CHANGELOG。

## 9. 本次改动的核对

优先检查模板结构、实际 JSON 字段、回调入口、动态初始化和样式作用域。关键交互需要时再进行最小浏览器验证，不默认全量测试、压缩或启动服务。

交付时分别说明文件已修改、静态关系已核对以及是否真正进行页面操作。保存、审批、删除等浏览器操作属于实际写库，仍需符合当次授权；未运行页面不能表述为浏览器验收通过。
